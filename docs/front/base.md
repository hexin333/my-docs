# 计算机基础

## 计算机存储基本单位

::: details 详情
**位（bit）**  
bit是计算机表示数据最小的单位，也叫比特位，一个位就代表一个0或1（即二进制）。

**字节（Byte，简写为B）**  
字节是计算机信息技术用于计量存储容量的一种计量单位，1byte等于8bit，1byte就是1B。

**KB（千字节）**  
1KB = 1024B（在计算机存储容量的度量上，按照2进制计算），但硬盘生产商是以1KB = 1000byte（按照10进制计算）。

**字符**  
字符是指计算机中使用的字母、数字、字和符号等。不同的编码方式下，字符与字节的换算关系不同。
:::

## 为什么使用二进制

::: details 详情

- 硬件实现简单：二进制只需要两个状态，通常用电压的高低来表示（如高电压表示 1，低电压表示 0）。这种简单的状态切换使得硬件电路设计更为简单和可靠
- 抗干扰能力强：在电路中，二进制的两个状态（0 和 1）可以通过明显的电压差来区分，这使得系统对噪声和干扰的容忍度更高，数据传输更稳定
- 逻辑运算方便：计算机的基本运算是逻辑运算，二进制系统与布尔代数非常契合，能够进行与，或，非等逻辑运算，简化了计算机的设计和操作
- 存储和处理效率高：二进制数据在计算机中可以直接存储和处理，避免了其他进制系统转换带来的复杂性和效率损失
- 历史和标准化：从计算机发展的早期，二进制就被广泛采用，形成了标准化的设计和技术积累，进一步推动了其普及和应用

:::

## 十进制整数转为二进制

::: details 详情
整数 9 转为二进制

```js
9 / 2 = 4 余 1
4 / 2 = 2 余 0
2 / 2 = 1 余 0
1 / 2 = 0 余 1
```

所以 9 的二进制就是余数`从下往上` 1001
:::

## 十进制小数转为二进制

::: details 详情
小数 0.375 转为二进制

```js
0.375 × 2 = 0.75 (取整 0)
0.75 × 2 = 1.5 (取整 1)
0.5 × 2 = 1 (取整 1)
```

所以 0.375 的二进制就是取整`从上往下` 0.011
:::

## 十进制负数转为二进制

::: details 详情
整数 -2 的二进制

```js
2 的原码：1000 0010 // 原码就是最简单的表示方法，注意有个符号位
2 的反码：1111 1101 // 反码是原码的反向，符号位不变
2 的补码：1111 1110 // 补码是反码加 1
```

所以 -2 的二进制就是 1111 1110
:::

## 原码/反码/补码

::: details 详情
**原码**  
原码其实是最容易理解的，只不过需要利用二进制中的第一位来表示符号位，0表示正数，1表示负数

| 十进制 | 原码      |
| ------ | --------- |
| 2      | 0000 0010 |
| -2     | 1000 0010 |

**反码**  
正数的反码和原码一样，负数的反码就是在原码的基础上符号位保持不变，其他位取反。

| 十进制 | 原码      | 反码      |
| ------ | --------- | --------- |
| 2      | 0000 0010 | 0000 0010 |
| -2     | 1000 0010 | 1111 1101 |

**补码**  
正数的补码和原码、反码一样，负数的补码就是反码+1

| 十进制 | 原码      | 反码      | 补码      |
| ------ | --------- | --------- | --------- |
| 2      | 0000 0010 | 0000 0010 | 0000 0010 |
| -2     | 1000 0010 | 1111 1101 | 1111 1110 |

为什么用补码？  
| 原因 | 说明 |
| ---------- | -------------------------- |
| **统一加减法** | 减法变加法，无需额外硬件 |
| **唯一零** | 原码和反码有 +0 和 -0，补码只有一个 0 |
| **多表示一个数** | 8 位补码范围：-128 ~ 127（比原码多一个） |

刚好加到符号位需要进1的情况，符号位怎么办？

```js
-1 的补码：1111 1111
-1 的补码：1111 1111
───────────────
相加：
  1111 1111
+ 1111 1111
───────────────
 1 1111 1110   ← 最高位产生进位 1

丢弃进位后：1111 1110  = -2 的补码
```

求补码的过程中，反码 + 1 时如果符号位产生进位时，也是同样的处理逻辑  
**符号位参与运算，进位自然丢弃**

:::

## 最大十进制整数

::: details 详情
| 位数 | 无符号最大 | 有符号最大 | 有符号最小 |
| ---- | ------------------------ | ------------------------ | ---------------------- |
| 8 位 | 2⁸ - 1 = **255** | 2⁷ - 1 = **127** | -2⁷ = **-128** |
| 16 位 | 2¹⁶ - 1 = **65535** | 2¹⁵ - 1 = **32767** | -2¹⁵ = **-32768** |
| 32 位 | 2³² - 1 ≈ **42.9 亿** | 2³¹ - 1 ≈ **21.4 亿** | -2³¹ ≈ **-21.4 亿** |
| 64 位 | 2⁶⁴ - 1 ≈ **1.8 × 10¹⁹** | 2⁶³ - 1 ≈ **9.2 × 10¹⁸** | -2⁶³ ≈ **-9.2 × 10¹⁸** |

n 位无符号最大 2ⁿ - 1；n 位有符号补码最大 2ⁿ⁻¹ - 1，最小 -2ⁿ⁻¹
:::

## JS中Number精度丢失问题

::: details 详情

- 十进制中的0.1在二进制中是无限循环小数，无法精确表示，只能进行四舍五入处理，这会导致精度丢失
- JavaScript中的Number类型采用64位（8字节）双精度浮点数表示其中1位用于符号位，11位用于指数位，52位用于尾位。这意味着尾数位最大只能表示52位的二进制数，超过这个范围的数值无法精确存储‌
- 加上隐含的前导1，只有在 -(2⁵³ - 1) 到 2⁵³ - 1 范围内（闭区间）的整数才能保证精度不丢失

:::

## 进程和线程的区别

::: details 详情
**进程**是操作系统中一个正在运行的程序，每个进程都有自己的地址空间、内存、文件描述符等资源。

**线程**是进程中的一个执行单元，是 cpu 调度的最小单元，共享进程的资源，但有自己的独立执行流。

区别

- 进程拥有独立的堆栈空间和数据段，需要分配独立的地址空间，开销大
- 线程开销小，切换快，没进程安全，从通信机制上看，线程可以共享数据段

例子

- 浏览器中一个 tab 就是一个进程，进程中某个线程崩了，整个进程就会崩，但是这不会影响其他的进程，因此进程之间相对独立
- Nginx 或 Nodejs PM2 开启的多个 instance 是进程，每个 instance 之间不能共享内存数据
- JS 中 WebWorker 是一个线程，它可以和和主线程共享内存数据，独立运行不阻塞 UI

:::

## JS单线程的原因

::: details 详情

- **简化并发编程‌**：单线程模型简化了并发编程的复杂性，避免了线程之间的数据同步和竞争条件等问题，使得开发者能够更容易地编写出健壮和可维护的代码‌
- **‌浏览器安全‌**：在浏览器环境中，JavaScript需要访问DOM来更新页面内容。如果多个线程同时访问和修改DOM，可能会导致不可预测的结果和数据不一致。单线程模型可以确保在任何时候只有一个线程可以访问和修改DOM，从而提高了浏览器的安全性‌
- **‌避免阻塞‌**：虽然JavaScript本身是单线程的，但浏览器通过异步编程模型（如事件循环、回调函数、Promises和async/await）来避免阻塞主线程。这意味着当JavaScript代码执行耗时操作时（如网络请求或定时器），主线程不会被阻塞，而是可以继续处理其他任务‌

:::

## JS如何利用多线程

::: details 详情

尽管JavaScript本身是单线程的，但它可以通过以下方式利用多线程的优势：

- Web Workers‌：Web Workers允许JavaScript创建新的线程来执行耗时的任务，如复杂的计算或数据处理。这些Worker线程与主线程并行运行，不会阻塞主线程，并且不能直接访问DOM，只能通过消息与主线程通信‌
- ‌异步操作‌：JavaScript大量使用异步操作来处理耗时任务，如网络请求和定时器。异步操作允许主线程在等待任务完成的同时继续执行其他任务，从而避免阻塞‌

:::
